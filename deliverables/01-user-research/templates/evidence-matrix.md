# Ma trận bằng chứng

> Chỉ điền sau phiên thật. Mỗi dòng phải truy được về ghi chép Pxx. Không điền ví dụ giả vì có thể bị hiểu nhầm là kết quả.

## Nhật ký bằng chứng cấp nguyên tử

| Mã bằng chứng | Pxx | Loại (`FACT/OBSERVATION/DIRECT_QUOTE`) | RQ | Đoạn hành trình | Nội dung đã ẩn danh | Bối cảnh/giới hạn |
|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |

## Diễn giải có truy vết

| Mã diễn giải | Diễn giải tạm thời | Mã bằng chứng ủng hộ | Mã bằng chứng phản bác/khác biệt | Số người / tổng số phiên hợp lệ | Giải thích cạnh tranh | Mức tin cậy và lý do | Quyết định: giữ/sửa/bỏ |
|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |

Không đếm nhiều quote của cùng một người thành nhiều người. Không ghi “đa số”, “phổ biến” hoặc tỷ lệ nếu không kèm số đếm thật và mẫu số. Một tín hiệu đơn lẻ là trường hợp, không phải mẫu lặp.

## Kiểm tra giả thuyết proposal

| Giả thuyết cần kiểm chứng | Bằng chứng ủng hộ | Bằng chứng phản bác/biến thể | Trạng thái (`chưa có dữ liệu/đang mở/có bằng chứng giới hạn`) |
|---|---|---|---|
| Chờ phản hồi khi đặt lịch |  |  | chưa có dữ liệu |
| Xác nhận không rõ hoặc ghi nhận sai |  |  | chưa có dữ liệu |
| Yêu cầu đặc biệt phải nhắc lại/không đến đúng người |  |  | chưa có dữ liệu |
| Phải chủ động liên hệ để biết tiến độ |  |  | chưa có dữ liệu |
| Lịch sử chăm sóc phân tán/khó tra cứu |  |  | chưa có dữ liệu |
| Các đặc điểm và bối cảnh của “chị Lan” đại diện cho mẫu |  |  | chưa có dữ liệu |

## Cổng trước artifact thiết kế

- [ ] Có tối thiểu 5 phiên hợp lệ và ghi rõ cách tuyển/giới hạn mẫu.
- [ ] Mọi diễn giải trỏ tới bằng chứng, có phản chứng/khác biệt và giải thích cạnh tranh.
- [ ] Quote được phép sử dụng, đúng nguyên văn và đã ẩn danh.
- [ ] Ba thành viên kiểm tra chéo; bất đồng còn lại được ghi rõ.
- [ ] Persona/VPC/scenario (nếu tạo ở task sau) chỉ dùng diễn giải đã qua cổng, không dùng giả thuyết chưa có dữ liệu.
